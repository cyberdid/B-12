## Першоджерело для Qt

Офіційний Qt for Python описує прозорість top-level widget через WA_TranslucentBackground; для X11 потрібні ARGB visual та compositing window manager. WindowStaysOnTopHint є запитом до віконного менеджера, не гарантією кожного WM. QSystemTrayIcon працює в Linux середовищах зі StatusNotifierItem або XEmbed і має isSystemTrayAvailable() для fallback. [Qt QWidget](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QWidget.html), [Qt window flags](https://doc.qt.io/qtforpython-6/PySide6/QtCore/Qt.html), [Qt system tray](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QSystemTrayIcon.html), [PySide6-Essentials](https://pypi.org/project/PySide6-Essentials/).

## Синтез і межі

- **Перевірений факт:** B-12 уже має stream chat, session/history, memory, consent, exact approval, cancellation/resume, voice status/mute, локальний owner-authenticated API та власний cybercat atlas.
- **Пропозиція:** desktop shell огортає ці API можливості, не створює другий agent. Анімація інформує користувача, не створює model/tool calls.
- **Вимога з brief/AGENTS:** local-first; permission/consent на контрольному шляху; один runtime-owner; mic/audio не запускається без явної дії; art має provenance.
- **Потребує перевірки:** X11 compositing/topmost/tray на цільовому хості; Wayland; desktop packaging; довгі streaming/error cycles. Огляд не підтверджує Windows/macOS сумісність.

## Повторний функціональний gap review — 08.11.2026

**Перевірений факт:** pinned `Capri-Capricorn-The-Desktop-Construct` відкриває окреме 420×520 chat window біля персонажа; це proximity-взірець, а не bubble в одному overlay. B-12 додає власну компактну frameless-панель і лишає `ChatWindow` контролером сесії, історії, streaming, cancel та approvals.

**Перевірений факт:** `kystt29/capricorn` має GUI для сайтів, програм і фраз-відповідей. B-12 додає локальні prompt shortcuts, що лише заповнюють composer, owner-authored application launchers з абсолютним executable і argv, а також HTTP(S) site shortcuts, які відкриваються тільки після кліку. Клік запуску програми підтверджується.

**Перевірений факт:** `mochiiwuff/capri-desktop` має compact status/progress, notification priority і persistent reminders зі snooze/dismiss. B-12 додає локальні нагадування з явним date/time picker, due notification та snooze/dismiss. Natural-language час не парситься. Approval лишається пріоритетним; статус ходу показується в bubble без popup.

**Вимога власника (08.11.2026):** запуск програм і системні команди потрібні у desktop-companion. Launcher працює тільки після кліку власника, запускає точний абсолютний executable/argv без shell і показує confirm. Shell-команда готується в UI як повідомлення для B-12; її виконання проходить існуючі `shell_exec`/grant/approval межі, не прямий `QProcess` і не дає моделі нових дозволів. Див. [ADR-011](../project/decisions.md#adr-011--desktop-launchers--system-commands).

**Не переносити:** автоматичний запуск, довільні model-triggered віконні/клавіатурні/процесні дії, Telegram auto-typing, неперевірені voice hooks і періодичний unsolicited chatter. Ні зовнішній код, ні artwork не копіюються.

**Окрема перевірка hook schema (08.11.2026):** офіційна [Antigravity Hooks documentation](https://antigravity.google/docs/hooks) розрізняє grouped handlers для `PreToolUse`/`PostToolUse` і direct handlers для lifecycle events; hooks отримують JSON через stdin і повертають JSON через stdout. `PreToolUse` вимагає `decision`; B-12 повертає `allow`, що делегує наступному hook/default policy. `Stop` теж вимагає рішення; B-12 повертає `stop`, щоб дозволити штатне завершення, а для інших подій повертає `{}`. Сумісність із реальною встановленою версією Antigravity не перевірялась.

**Статус B-12 таблиці:** це зіставлення вихідного коду й реалізаційних меж у робочій гілці, не host acceptance і не доказ встановлення hooks. Статичні перевірки та навмисні пропуски будуть зафіксовані окремо в [implementation plan](../../docs/superpowers/plans/2026-11-08-b12-capri-feature-parity.md) і журналі.

B-12 переосмислює функціональність власним кодом; не переносить upstream files, artwork, cut-ins, sounds або copied text.

**Висновок для B-12:** найвиразніші приклади саме системного опису характеру — `Modelfile` у Desktop Construct та `persona.py` у `kystt29/capricorn`; найбільше пов’язаних із desktop-поведінкою модулів — у `mochiiwuff/capri-desktop`. Це джерела для аналізу структури, не офіційний канон Capri. За вимогою власника базову манеру Capri та профіль preferences реалізовано самостійним текстом у [`src/b12/persona.py`](../../src/b12/persona.py), [`src/b12/agent.py`](../../src/b12/agent.py) та desktop UI; upstream prompts і authored lines не копіюються. Профіль автоматично додається до desktop-запиту як bounded style-only context і передається обраному model provider. Поведінку ще треба оцінити на цільовій моделі. Upstream code/assets ліцензуються окремо; див. попередні межі ліцензії на цій сторінці.
