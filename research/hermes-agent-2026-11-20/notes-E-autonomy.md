# E. Автономія: /goal, /heartbeat, /loop, cron — нотатки

Джерело: `hermes-agent` @ `514e2cbd`: `user-guide/features/goals.md`, `heartbeat.md`, `loops.md`, `cron.md` (розділи: what cron can do, admission recovery, catch-up, agent-managed scheduling, failure nudge, re-runs, UNVERIFIED, silent, CRON_FAILURE). Наш бік: `src/b12/goals.py`, `autonomy.py`, `attention.py`, `initiative.py`; ADR-017, ADR-018.

## Hermes
- **`/goal` (Ralph loop, на основі Codex CLI):** ціль у поточній сесії; після кожного ходу легка модель-суддя повертає `done | continue | blocked | wait` з причиною. При `continue` система сама подає продовження як user message. Бюджет — 20 ходів, після нього пауза.
  - Суддя бачить **лише останню відповідь агента (~4 КБ)**: «done лише якщо відповідь явно підтверджує». Тобто вирішує за самозвітом. Якщо суддя впав — fail-open (`continue`), а справжнім запобіжником лишається бюджет.
  - **Контракт завершення** (опційний): `outcome`, `verification`, `constraints`, `boundaries`, `stop_when`; `/goal draft` — модель розгортає однорядкову ціль у контракт, власник переглядає. Суддя тоді вимагає конкретного доказу (вивід команди, фрагмент файла).
  - **`/subgoal`** — додає критерій без скидання циклу.
  - **Quality gates:** shell-команда, що має повернути 0, перш ніж суддю взагалі покличуть; хвіст виводу падіння стає наступним промптом; 3 спроби, 5 хв таймаут, далі пауза.
  - **Очікування процесу:** суддя бачить фонові процеси сесії й може «запаркувати» ціль (`wait_on_pid/session/seconds`) замість «ну що, готово?» кожен хід.
  - Повідомлення користувача завжди мають пріоритет; нову ціль посеред ходу відхилено.
- **`/heartbeat`:** одна повторювана інструкція на сесію; лише коли сесія простоює; пропущені тики зливаються в один; відповідь-маркер `NO_REPLY`/`[SILENT]` → нічого не надсилається, без індикаторів набору; промпт має «don't-invent-work guard»: якщо нічого не змінилось — коротко й стоп.
- **`/loop`:** фіксований інтервал або самостійний темп: почати з 1 хв, при однакових відповідях експоненційно до 15 хв, при зміні — назад до мінімуму (локальний дайджест відповіді). Зупинка: `LOOP_COMPLETE`, `--times N`, `--until <умова>` (той самий суддя), бюджет 100 тиків. Активна ціль має пріоритет над циклом.
- **cron:** окремі свіжі сесії; ідентичність запуску зберігається до доставки; **«доставка, перервана після claim, лишається unknown і автоматично не повторюється»**; перерваний запуск — на паузу для оператора. Вікно надолуження (половина періоду, 2 хв–2 год). Повтори лише коли не було жодного виклику моделі (5/15/30 хв — «spend-neutral, не може подвоїти ефект»). `failure_streak` → підказка «виправ/пауза/видали» після 3. `[SILENT]` для «звітуй лише коли погано» (провали доставляються завжди). `[CRON_FAILURE]` — агент сам оголошує невдалий запуск (суворо: лише перший рядок). Доставка без доказу (`message_id`) → `UNVERIFIED`. Cron-сесії не можуть створювати cron-задачі (за замовчуванням), щоб не було «рекурсивного планування».
- **Kanban / делегування:** окремі воркери й профілі; для Capri з однією локальною моделлю малоактуально (не вивчав детально).

## B-12 (звірено з кодом)
- `goals.py`: тривалі цілі; **початковий намір незмінний (тригер SQLite)**; бюджет ходів переживає рестарт; `achieved` лише з живим доказом через спільний resolver і `check_spec` — **«ніколи за заявою моделі»**; перевірки поки лише `file_contains`.
- `autonomy.py`: один планувальник (flock), фонові ходи цілей у простої, рефлексія раз на 6 год; зупинка власником зупиняє виконання.
- ADR-017: журнал кроків з ключем ефекту між ходами; `unknown` ніколи не повторюється наосліп; верифікатори для file_write/memory_store/note_add; решта → `needs_owner`.
- ADR-018: фільтр ініціативи `drop / needs_owner / deliver / defer / inbox`, новизна, дедуп 24 год, тихі години, черга, `mute_goal`.
- Немає: ціль «у поточній розмові» з автопродовженням; контракту завершення як структури; підцілей; очікування процесу; самостійного темпу; cron-задач від власника з доставкою.

## Порівняння (чесно)
| | Краще в Hermes | Краще в B-12 |
|---|---|---|
| Критерій «виконано» | — : LLM-суддя за самозвітом, fail-open; gates — лише shell | **так**: живий доказ + довірена перевірка, ніколи заява моделі |
| Різноманіття перевірок | **так**: будь-яка shell-команда як gate | лише `file_contains` |
| Формулювання цілі | **так**: контракт (outcome/verification/constraints/boundaries/stop_when), `/goal draft`, `/subgoal` | `intent` + `criteria` як текст; незмінність наміру — у нас краще |
| Робота «поки я тут» | **так**: Ralph loop у поточній сесії | лише фонові ходи у простої |
| Ідемпотентність після збою | на рівні cron-доставки (unknown не повторюється) | **так**: журнал кроків на рівні кожного ефекту (ADR-017) |
| Не говорити дарма | `[SILENT]`, don't-invent-work, self-paced backoff | **так, глибше**: детермінований фільтр з новизною, дедупом, тихими годинами, чергою, mute |
| Очікування зовнішнього процесу | **так** (`wait_on_pid`) | немає |
| Розклади власника | **так** (cron з доставкою, вікно надолуження, failure streak) | немає (лише `review_interval_s` цілі) |

## Кандидати на перенесення
1. **Контракт завершення для цілей:** поля `verification`, `constraints`, `boundaries`, `stop_when` у `goals` (поряд з незмінним `intent`); `stop_when` → `needs_owner`. Модель може запропонувати контракт, власник підтверджує контрольним шляхом.
2. **Більше типів довірених перевірок** замість shell-gates: `command_exit_zero` з allowlist у пісочниці, `file_sha256`, `http_status` — лише з гранту. Суддю-LLM не брати як критерій «виконано»; він допустимий лише як підказка «продовжувати чи ні».
3. **Маркери тиші й самооголошення невдачі** у фонових ходах: `[SILENT]` → `drop` у фільтрі ініціативи без участі моделі в рішенні; `[GOAL_BLOCKED]` → пауза з причиною.
4. **Повтор лише якщо модель не викликалась** (spend-neutral) — для фонових ходів після збою мережі/Ollama.
5. **`failure_streak` для цілей** — після 3 невдач підряд пауза з підказкою власнику.
6. **Нагадування/розклад від власника** («щоранку о 8 — підсумок») — як ціль з cron-виразом і доставкою через фільтр ініціативи. Корисно для компаньйона; окремий ADR.
