# A–B. Цикл агента і збирання промпту — нотатки

Джерело: `NousResearch/hermes-agent` @ `514e2cbd`, `agent/AGENTS.md`, `website/docs/developer-guide/agent-loop.md`, `prompt-assembly.md`. Наш бік звірено з `src/b12/agent.py`, `context.py`.

## Hermes (док / код)
- Цикл синхронний; кожна фаза ітерації — окремий модуль `turn_*.py` (~600 рядків кожен): preflight, request assembly, api call, api error, empty response, tool round/validation, overflow, truncation, recovery, autorecover (драбина wait-and-retry після вичерпання), stop gates, liveness, finalizer.
- Бюджет ітерацій 500 (субагенти — по 50, незалежні); на 100 % — зупинка з підсумком; «одна грейс-відповідь» після вичерпання.
- Переривання: HTTP-виклик у фоновому потоці, головний чекає відповідь/переривання/таймаут; при перериванні відповідь відкидається, часткова не потрапляє в історію.
- Кілька викликів інструментів — паралельно через ThreadPoolExecutor, крім інтерактивних (`clarify`); результати в порядку викликів.
- Агентні інструменти (`todo`, `memory`, `session_search`, `delegate_task`) перехоплюються до реєстру — таблиця `INLINE_TOOL_EXECUTORS`.
- Fallback-провайдери: 429/5xx/401/403 → наступний провайдер зі списку; окремі ланцюжки для допоміжних задач (стиснення, vision, заголовки).
- `/steer` — єдиний легальний спосіб вставити повідомлення користувача посеред ходу (після tool result).
- Колбеки: tool_progress, thinking, reasoning, clarify, step, stream_delta, tool_gen, status.

### Промпт
- Три яруси: stable (SOUL.md/ідентичність, настанови щодо інструментів) → context (системне повідомлення, AGENTS.md тощо, git-знімок) → volatile (індекс навичок, MEMORY.md, USER.md, блок провайдера пам'яті, час/сесія/модель, середовище).
- Байтово стабільний на всю сесію; єдиний дозволений злам кешу — стиснення. Зміни посеред сесії — одноразовою приміткою в user message або tool result.
- Дефолтна ідентичність: «відповідай довжиною, що відповідає вазі запиту… без filler… погоджуйся, бо це правильно, а не тому, що сказав користувач… глибина — коли просять».
- Контекстні файли скануються на ін'єкції (невидимий юнікод, «ignore previous», ексфільтрація) → `[BLOCKED]`; обрізання 70/20 голова/хвіст.
- **«Prompt surface» у CI**: повний відрендерений системний промпт + `tools[]` для 9 поверхонь комітиться як фікстура; тест падає при зміні; PR показує дельту токенів і промпту; зміна потребує схвалення core.

## B-12 (звірено з кодом)
- Асинхронний цикл `Agent._drive` (≈450 рядків в одній функції) з подіями `turn_started … turn_completed/failed/cancelled`; рівно одна термінальна подія; очікування схвалення не термінальне, хід відновлюється з тим самим id.
- Скасування через `asyncio.Event`, `invalidate_active`; часткова/скасована відповідь не комітиться — те саме, що в Hermes.
- Виклики інструментів виконуються **послідовно** (`_run_calls`, черга).
- Захист від зациклення: `repeated_failure`, `repeated_call`, `_same_report` → `stalled`, `max_rounds`; режим persist з резервом раундів на звіт.
- Стиснення історії: обрізання/відкидання старих повідомлень (`_fit_history`, драбина `_PERSIST_FIT`) + примітка про пропущене (`_history_continuity_note`); **LLM-підсумку немає**.
- Системний промпт: політика доступу + персона Capri + (за прапорцями) цілі, вподобання; докази пам'яті після повідомлення користувача.
- Fallback-провайдера немає (локальна модель, `reset_provider`).
- Фікстури повного промпту в тестах немає.

## Порівняння (чесно)
| | Краще в Hermes | Краще в B-12 |
|---|---|---|
| Структура циклу | фази в окремих модулях — легше змінювати й тестувати | — (наш `_drive` монолітний) |
| Паралельні інструменти | є | немає; для голосового компаньйона з малою моделлю менш важливо, але read-only виклики можна паралелити |
| Переривання | рівноцінно | рівноцінно + явні події й одна термінальна подія, схвалення як пауза ходу |
| Стиснення | LLM-підсумок + обрізання tool results | лише обрізання; ризик втрати змісту довгої розмови |
| Кеш промпту | інваріант, тести | не є інваріантом; для локальної Ollama кеш KV префікса теж економить TTFT — **потребує перевірки** на нашому стеку |
| Контроль змін промпту | фікстура «prompt surface» у CI | немає — легко непомітно змінити промпт |
| Захист від зациклення | бюджет + грейс | детальніші детектори повторів (repeated_call/failure, same_report) |

## Кандидати на перенесення
1. **Фікстура «prompt surface»**: тест, що рендерить повний системний промпт і схеми інструментів для CLI/voice/web і порівнює зі знімком. Дешево, корисно (ми вже ловили непомітні зміни промпту в оцінках).
2. **Стабільний префікс**: перенести мінливі частини (час, цілі, вподобання) після стабільної частини і виміряти TTFT на Ollama з теплим кешем.
3. **Паралельні read-only виклики** (file_read, memory_search) — лише після вимірювання; не для дій з ефектами.
4. **Розбити `_drive` на фази** — рефакторинг без зміни поведінки; не пріоритет.
