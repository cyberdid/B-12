## Hermes
- **Навичка** — тека з `SKILL.md` (frontmatter: name, description ≤60 симв., platforms, умови активації) + `references/`, `templates/`, `scripts/`, `assets/`. Сумісно зі стандартом agentskills.io.
- **Поступове розкриття:** у промпті лише індекс (назва + опис); `skill_view(name)` завантажує повний текст, `skill_view(name, path)` — окремий файл. Ціна — пропорційна потребі.
- **Виклик:** `/назва` (до 5 навичок поспіль), набори (`bundles`) у YAML; ін'єкція йде user message — кеш не ламається.
- **`skill_manage`:** create / patch (old→new) / patch повним вмістом / delete / write_file / remove_file. Окремі «слоти» тексту на кожну дію; неправильний слот відхиляє весь пакет до застосування. Лінтер-порадник: `incident-log-shape` (тіло з номерами PR — це журнал, а не урок), `references-sprawl` (>60 файлів), `oversized-body` (>24 тис. симв.).
- **Що таке хороша навичка** (з промпту рев'ю): процедура по кроках з командами; пастка = загальне правило + одне речення «чому», прив'язане до кроку; без дат, номерів, цитат; той самий урок двічі = одне правило; не дублювати AGENTS.md і схеми інструментів; виправляти на місці, а не дописувати «UPDATE: насправді…».
- **`/learn`:** з документації, URL, книги чи «того, що я щойно показав» — агент сам пише навичку; великі джерела → «база знань» (короткий SKILL.md + розділи в `references/`), без відтворення тексту джерела.
- **Довіра:** навички з клонованого репо не завантажуються без `hermes skills trust`; хаб-навички — карантин, сканування, хеш.
- **`write_approval` для навичок:** увімкнений гейт ставить у чергу будь-який запис (навіть з основного ходу), з `diff`; рекомендовано для малих моделей («small models that misjudge what they learned»).
- **Куратор:** раз на 7 днів, коли агент простоює ≥2 год. Детерміновано: невживане 14 днів → `stale`, 30 днів → `.archive/` (відновлюване). Ніколи не чіпає закріплені (`pin`) і ті, на які посилається cron; навичка, яку жодного разу не вживали, має «пільговий» мінімальний вік. LLM-консолідація (об'єднання в «парасольки») **вимкнена за замовчуванням**, перед нею знімок tar.gz; `lock` забороняє агенту зміни.
- **Журнал мутацій** (JSONL, append-only): actor (`curator`/`agent`/`user`), дія, причина, sha256 файлів до/після, блоби за вмістом; відкат однієї мутації; телеметрія, а не гейт.

## Чи переносити в Capri
**Пропозиція (потребує рішення власника, Q10):** так, але вузько.
1. **Навички як документи власника + агента** у `~/.local/state/b12/skills/<name>/SKILL.md` з тим самим форматом (сумісність з agentskills.io — бонус: можна брати готові).
2. **Індекс у промпті, повний текст за потреби** (`skill_view` як read-only інструмент) — дешево для контексту малої моделі.
3. **Створення/зміна агентом — лише через чергу схвалення** (як `write_approval: true`), бо модель мала; власник бачить diff у веб-інтерфейсі.
4. **Провенанс:** кожна зміна навички посилається на хід/сесію, з якої виведена; забування сесії → позначка «навичка втратила джерело» (не автоматичне видалення).
5. **Куратор у детермінованому режимі** (stale/archive за невживання, без LLM-консолідації).
6. **Вимірювання до ввімкнення:** набір «повторна задача»: та сама задача двічі з перервою; метрика — менше кроків/помилок у другому проході при незмінній якості. Без цього — не вмикати.
