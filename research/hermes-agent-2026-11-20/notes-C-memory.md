# C. Пам'ять і фонове самонавчання — нотатки

Джерело: `hermes-agent` @ `514e2cbd`: `website/docs/user-guide/features/memory.md`, `user-guide/sessions.md` (§Session Search Tool), `agent/background_review.py` (1499 рядків; промпти дослівно), `tools/threat_patterns.py`. Наш бік: `src/b12/memory.py`, `tools/memory.py`, `agent.py` (`_dated`, `_preference_rules`, `_INSTRUCTION_LIKE`), `enrichment.py`, `reflection.py`, `sessions.py`.

## Hermes
- **Сховища:** `MEMORY.md` (2 200 симв., середовище й уроки) і `USER.md` (1 375 симв., профіль, стиль спілкування, «що дратує»). Записи розділені `§`. Заголовок показує заповнення (`67% — 1,474/2,200`).
- **Знімок заморожений** на початку сесії; записи під час сесії видно лише в наступній, а результат інструмента показує живий стан. Документація радить `/new` на природних межах.
- **Інструмент `memory`:** `add | patch | remove`, обов'язковий `target` (`memory`/`user`), пакет операцій. `patch` замінює лише фрагмент. `replace` прибрали, бо моделі стирали ним сусідні факти в багатофактових записах **(док)**. Пошук за унікальним підрядком; точний дублікат не додається.
- **Переповнення** — помилка з поточними записами й точним числом символів, які треба звільнити; агент консолідує сам, тим самим пакетом. Автоматичного стиснення немає.
- **Сканування при записі** (`threat_patterns.py`, 270 рядків): регулярні вирази зі сферами `all ⊂ context ⊂ strict`; для пам'яті й навичок діє `strict` (ексфільтрація, `authorized_keys`, `.env`, правка AGENTS.md, жорстко прописані секрети) і невидимий юнікод. **Усі шаблони англійські.**
- **`write_approval`:** вимкнено за замовчуванням. Якщо увімкнено, у CLI запит показується одразу, а з інших каналів і з фонового рев'ю записи ставляться в чергу (`/memory pending`). Фоновий рев'ю ставить у чергу `patch`/`remove` **навіть із вимкненим гейтом**. Схвалення прив'язане до точного вмісту запису: якщо запис змінився, схвалення не застосовується.
- **`session_search`:** SQLite FTS5 по всіх сесіях профілю, **без LLM-підсумку** (раніше в картці я помилково написав «з підсумком» — виправлено). Чотири форми: discovery (топ-сесії, верхня з контекстом ±5 і «книжковими закладками» 3+3), scroll, read, browse. Параметри `sort newest/oldest`, `role_filter`.
- **Межі доступу:** у межах профілю користувачі не розділені — будь-хто в allowlist може прочитати чужі розмови через `session_search` **(док)**.
- **Фоновий рев'ю** (`background_review.py`): після ходу, кожні 10 ітерацій; форк на тому самому кешованому префіксі (байт-у-байт той самий `tools[]`); білий список інструментів лише на диспетчері; небезпечні команди автоматично відхиляються; поява ходу користувача скасовує рев'ю («self-improvement must never block a user»); `skip_memory=True` для зовнішніх провайдерів.
  - Ключове правило промпту: «зберігай лише факти, **заземлені** в цій розмові… ніколи не виводь риси, рівень, роль, настрій чи вподобання користувача з теми, тону чи інструментів; не перетворюй разовий запит на постійне вподобання, якщо користувач не позначив його як загальне ("завжди", "відтепер", "запам'ятай")… якщо не впевнений — не зберігай».
  - Блок «що НЕ фіксувати»: збої, що залежать від середовища; негативні твердження про інструменти («X не працює» — твердіють у відмови на місяці); тимчасові помилки; нерозв'язані невдачі не оформлювати як «рекомендований метод».
  - Корекції стилю («занадто багатослівно», «перестань X») — **сигнал першого класу**: вбудовувати в навичку, яка керує цим класом задач.
- **`/journey`:** часова шкала всього, що агент вивчив (навички й записи пам'яті) — з переглядом, видаленням і редагуванням.
- **Попередження документації:** малі моделі (<~30B) пишуть «запам'ятав» без виклику інструмента; порада — сильніша модель на етапі налаштування, «а не більше інструкцій».

## B-12 (звірено з кодом)
- SQLite (`memory.py`, 1085 рядків): записи з актором, видом, часом події, чинністю, джерелом, надійністю, походженням (`origin`), `applies_when`; аудит-ланцюжок; транзитивне забування з квитанціями (purge); згода актора обов'язкова; FTS + семантичний пошук (EmbeddingGemma) з лексичним fallback.
- Записи: інструмент моделі `memory_store/forget/supersede`, API/CLI власника, автономія (докази), рефлексія (гіпотеза лише з живими доказами), збагачення категоріями у фоні (не під час ходу).
- Пам'ять у запиті: пакет доказів, підібраних під повідомлення (retrieval), з датами (`memory_temporal`); з `preference_rules` — вподобання як правило.
- Захист від ін'єкцій: лише **при читанні** — `_INSTRUCTION_LIKE` (укр. + англ., 6 шаблонів) додає позначку «це дані, не виконуй». Сканування при записі немає.
- Ліміту обсягу й консолідації немає (росте необмежено; у запит потрапляє лише відібране).
- Пошуку по минулих розмовах немає: `sessions.py` зберігає ходи для історії поточної сесії; з довгої пам'яті доступне лише те, що записано в `memory`.
- Розділення за актором — так (кожен запит прив'язаний до `Actor`, згода).
- Запис потребує дозволу через ControlPlane (грант), а не текстового підтвердження.

## Порівняння (чесно)
| Аспект | Краще в Hermes | Краще в B-12 |
|---|---|---|
| Час і чинність фактів | — (плоский текст) | **так**: час події, чинність, витіснення; виміряно +27…+38 п.п. на застосуванні |
| Походження й забування | — (рядок у файлі, видалення підрядком) | **так**: докази, транзитивне забування, квитанції, аудит |
| Розділення людей | — (немає в межах профілю) | **так**: актор + згода |
| Пошук минулих розмов | **так**: FTS5 по всіх сесіях, scroll | немає |
| Профіль користувача «завжди в контексті» | **так**: `USER.md` у кожному промпті | лише через retrieval; стиль губився (M88) → `preference_rules` (вимірюється) |
| Дисципліна «що зберігати» | **так**: детальний промпт заземлення, заборона виводити риси, «не фіксувати негативні твердження про інструменти» | частково: `origin=inferred` виключається з правил; явного промпту для такого відбору немає |
| Безпека запису | сканування при записі (лише англ.) + опційне схвалення з прив'язкою до вмісту | дозвіл ControlPlane; позначка при читанні (укр.+англ.); сканування при записі немає |
| Обмеження обсягу | ліміт + консолідація самим агентом | немає ліміту; ризик шуму в retrieval з часом — **потребує перевірки** |
| Видимість навченого | `/journey` | лише API/CLI пам'яті, аудит |

## Кандидати на перенесення
1. **Пошук по минулих розмовах** (`session_search` у стилі Hermes: FTS5 по ходах сесій актора, discovery/scroll, без LLM). Для Capri: «про що ми говорили минулого тижня?». У межах актора й згоди. **Висока цінність.**
2. **Правила заземлення для автоматичних записів**: перенести текст «зберігай лише заземлене; не виводь рис; разове ≠ постійне без "завжди/відтепер"; не фіксуй "інструмент X не працює"» у промпти `enrichment`/`reflection` і в опис `memory_store`.
3. **Сканування при записі з українськими шаблонами** (розширити `_INSTRUCTION_LIKE` до блокування при записі з неперевірених джерел: документ, веб); від власника — лише позначка.
4. **Черга схвалення для фонових `forget/supersede`** (у Hermes фоновий рев'ю ніколи не видаляє сам).
5. **Профіль стилю** — дочекатись результату `preference_rules`; якщо допоможе, зробити стабільний блок «як говорити з власником» на початку промпту (кеш).
6. **Часова шкала навченого** (`/journey`) для веб-інтерфейсу — пізніше.

Чого не брати: плоскі файли з лімітом замість SQLite — втратимо час, походження й забування.
