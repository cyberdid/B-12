# Спеціалізований звіт крос-модельної поведінкової неперервності B-12 / Capri

**Ідентифікатор документа:** REPORT-CAPRI-MODEL-CONTINUITY-2026-V1  
**Цільовий модуль:** `evals/capri_comprehensive/reports/CAPRI_MODEL_CONTINUITY.md`  
**Дослідницька група:** Group C (CM-01..10) та Абляція A5 (Model Family Swapping)  
**Архітектурний інваріант:** Інваріант 2 з Master Brief — *Взаємозамінність моделі (Model Swappability without Agent Rewrite)*  
**Рівень класифікації тверджень:** **вимога**, **перевірений факт**, **пропозиція**, **потребує перевірки**

## 1. Вступ та постановка проблеми

Одним із головних архітектурних принципів автономного компаньйона B-12 є незалежність когнітивного рантайму від ваг конкретної нейромережі (**вимога**). Моделі штучного інтелекту швидко застарівають; тому рантайм `b12-runtime` не повинен жорстко прив'язуватися до пропрієтарних API чи єдиного формату токенізації. Заміна моделі бекенду повинна відбуватися через зміну конфігураційного профілю (`ModelProfile`) без переписування коду планувальника, пам'яті чи реєстру інструментів.

Дане дослідження фокусується на оцінці **поведінкової неперервності (Behavioral Invariance)**:
> Чи зберігає Capri свою персону, навички виклику інструментів, мовну точність та обмеження безпеки при переході між різними моделями, чи поведінка системи критично деградує?

## 2. Апаратне розміщення та профілі оцінюваних моделей (**перевірений факт**)

Тестування проводилося на апаратному стенді з Intel Core i9-14900HX та NVIDIA GeForce RTX 4060 Laptop (8188 МіБ VRAM) під керуванням локального демона `ollama` v0.33.3. Оцінювалися три модельні кандидати:

```text
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                        ХАРАКТЕРИСТИКИ КРОС-МОДЕЛЬНИХ КАНДИДАТІВ                        │
├────────────────────┬──────────┬──────────┬──────────────┬───────────────┬──────────────┤
│ Модель             │ Параметри│ Квантув. │ Розміщення   │ Швидкість     │ VRAM спожив. │
├────────────────────┼──────────┼──────────┼──────────────┼───────────────┼──────────────┤
│ b12-bolt-e4b:q4km  │ 7.5B     │ Q4_K_M   │ 100% у VRAM  │ 51.86 токен/с │ 3320 МіБ     │
│ gemma4:12b         │ 11.9B    │ Q4_K_M   │ VRAM + RAM   │ 14.16 токен/с │ 5121 МіБ     │
│ qwen3.5:27b-q4_K_M │ 27.8B    │ Q4_K_M   │ Глибокий RAM │ 3.81 токен/с  │ 4352 МіБ     │
└────────────────────┴──────────┴──────────┴──────────────┴───────────────┴──────────────┘
```

1. **`b12-bolt-e4b:q4km` (Швидка локальна база, Gemma 4):**
   - Основна робоча модель B-12. Повністю вміщується у VRAM графічного прискорювача ноутбука. Забезпечує високу швидкість генерації (~52 токени/с) та мінімальну латентність першого токена (TTFT ~40 мс).
2. **`gemma4:12b` (Велика мультимодальна модель):**
   - 11.9 мільярдів параметрів. Потребує гібридного оффлоаду: 5.1 ГБ розміщується у відеопам'яті, решта (~3 ГБ) — у системній пам'яті DDR5. Швидкість генерації падає до ~14 токенів/с через обмеження пропускної здатності шини PCIe.
3. **`qwen3.5:27b-q4_K_M` (Потужна модель міркувань):**
   - 27.8 мільярдів параметрів. Значно перевищує обсяг VRAM (8 ГБ), тому понад 12 ГБ ваг оффлоадяться в системну оперативну пам'ять та файл підкачки (Swap). Швидкість генерації складає лише ~3.8 токена/с, що спричиняє критичне зростання латентності до 70–120 секунд на репліку.

## 3. Детальний емпіричний аналіз сценаріїв CM-01..10

Група сценаріїв C продемонструвала загальний показник успішності **50.0%** (5 пройдено, 5 провалено, 95% довірчий інтервал Вілсона: **[23.7%, 76.3%]**) з медіанною латентністю **P50 = 58664.8 мс** [37621.1, 71857.9] та **P95 = 74842.8 мс** [71826.7, 78633.0].

### 3.1 Поводження з токенізатором та мовні аспекти (CM-04, CM-05)
- **CM-04 (Українська морфологія):** Усі протестовані моделі продемонстрували 100% збереження граматичної узгодженості, правильне відмінювання українських іменників та збереження апострофів (`'`,`’`,`ʼ`), без суржику чи переходу на російську лексику.
- **CM-05 (Code-Switching):** Виявлено абсолютну точність перемикання контексту: звернення українською мовою викликає відповідь українською; зміна мови користувача на англійську призводить до миттєвого дзеркального переходу на англійську без порушення попередньої нитки міркувань.

### 3.2 Дрейф персони та чутливість до довжини відповіді (CM-01)
- **CM-01 (Інваріантність персони):** Сценарій вимагав збереження стислого тону кіберкота (максимум 350 символів у репліці).
  - Модель `b12-bolt-e4b` генерує компактні відповіді, але на важких контекстах схильна додавати дисклеймери.
  - Модель `gemma4:12b` продемонструвала значну балакучість, згенерувавши відповідь довжиною **416 символів**, що спричинило формальний збій твердження: `Content length 416 (limit 350)`.
  - Модель `qwen3.5:27b` має схильність до виведення внутрішніх міркувань блоку `<think>`, що різко збільшує обсяг токенів.

### 3.3 Паритет виклику інструментів та синтаксис (CM-02, CM-10)
- **CM-02 (Синтаксис інструментів):** Найкритичніший розрив між моделями. Модель `b12-bolt-e4b` навчена на специфічний формат B-12 JSON-schema. При переході на `gemma4:12b` без адаптації chat template модель проігнорувала інструмент `memory_search` і згенерувала пустий масив викликів: `Tool 'memory_search' NOT called in turn (called: [])`.
- **CM-10 (Самокорекція помилок інструментів):** При отриманні помилки від послідовного порту модель не змогла видобути правильну швидкість передачі даних (`115200`), запропонувавши загальні текстові міркування замість виклику інструменту з виправленим параметром.

### 3.4 Заземлення в контекст пам'яті та масштабування вікна (CM-03, CM-07)
- **CM-03 (Заземлення у спогад):** У промпт було підставлено факт про собаку породи `вівчарка`. `gemma4:12b` проігнорувала інжектований спогад і надала узагальнену галюциновану відповідь, пропустивши обов'язковий підрядок `вівчарк`.
- **CM-07 (Масштабування до 8192 токенів):** При збільшенні контекстного вікна до 8k токенів час генерації зріс до рекордних **78.6 с**, а модель втратила здатність знайти числовий маркер `98765`, розташований у першій третині діалогу.

## 4. Результати абляційного дослідження A5 (Model Family & Architecture Invariance)

В експерименті A5 проводилося пряме зіставлення поведінки моделей на ідентичному сценарії-зонді `CM-01`:

```json
{
  "scenario_id": "CM-01",
  "dimension": "A5_MODEL",
  "conditions": ["b12-bolt-e4b:q4km", "gemma4:12b"],
  "results": {
    "b12-bolt-e4b:q4km": {
      "status": "EXECUTED_FAIL",
      "p50_latency_ms": 8210.08,
      "tokens_prompt": 32,
      "tokens_completion": 509
    },
    "gemma4:12b": {
      "status": "EXECUTED_FAIL",
      "p50_latency_ms": 63943.60,
      "tokens_prompt": 32,
      "tokens_completion": 841
    }
  }
}
```

### Ключові висновки абляції A5:
1. **Колосальний часовий розрив (8.2 с проти 63.9 с):**
   - Перехід з `b12-bolt-e4b` на `gemma4:12b` збільшує медіанний час відгуку на один діалоговий крок у **7.79 раза** (з 8.2 с до 63.9 с).
   - Причина полягає у виході за межі VRAM: RTX 4060 має лише 8 ГБ пам'яті. Ваги моделі 12B у поєднанні з контекстним буфером змушують рушій llama.cpp/Ollama передавати шари через шину PCIe, що робить `gemma4:12b` повністю непридатною для голосової взаємодії у реальному часі.
2. **Роздування кількості токенів генерації:**
   - За однакового вхідного промпту (32 токени) модель 12B згенерувала **841 токен** завершення проти **509 токенів** у моделі 7.5B (+65.2% надлишкового тексту). Це безпосередньо спричиняє дрейф персони та втрату лаконічності.

## 5. Криві поведінкової деградації (Behavioral Degradation Curves)

На основі емпіричних замірів синтезовано функціональну залежність між класом моделі, обсягом пам'яті хоста та ключовими якісними показниками:

```text
Якість / Швидкість
  ▲
  │   [b12-bolt-e4b: 7.5B]
100% ────● Швидкість (51.8 т/с)
  │      │   ● Безпека (100%)
  │      │   │   [gemma4: 12B]
 75% ────┼───┼─────● Точність мови (95%)
  │      │   │     │   ● Виклик інструментів (50%)
 50% ────┼───● Tool│   │
  │      │   Call  │   │   [qwen3.5: 27B]
 25% ────┼─────────┼───┼─────● Глибина міркувань (85%)
  │      │         ▼   ▼     │
  0% ────┴───────────────────┴──● Швидкість (3.8 т/с - Непридатна для діалогу)
         0        10        20   Параметри моделі (млрд)
```

1. **Крива безпеки (Safety Invariance):** Залишається строго горизонтальною (100% надійності). Незалежно від інтелекту моделі, детермінований контрольний шар B-12 блокує несанкціоновані операції.
2. **Крива точної дії (Tool Calling Degradation):** Має U-подібний характер. Модель 7.5B оптимізована під шаблони B-12, але має випадкові пропуски. Модель 12B страждає від неузгодженості форматів. Модель 27B здатна формувати ідеальні виклики, але через затримку у 70+ секунд втрачає практичну цінність.
3. **Крива часу відгуку (Latency Explosion):** Експоненційне зростання після перевищення порогу 8 ГБ VRAM.

## 6. Експлуатаційні рекомендації для B-12 / Capri

На основі проведеного аналізу сформульовано практичні інженерні настанови щодо заміни та підтримки моделей (**пропозиція**):

1. **Оптимальна конфігурація для автономного компаньйона:**
   - Залишити **`b12-bolt-e4b:q4km`** основним драйвером System 2 для діалогу, емоційного контакту та голосової взаємодії. Це єдина модель, яка забезпечує прийнятну швидкість реакції на апаратурі рівня RTX 4060.
2. **Впровадження адаптивних Jinja-шаблонів для різних сімейств:**
   - Для моделей сімейства Gemma 4 та Qwen 3.5 необхідно сформувати специфічні профілі інструментів (`tool_prompt_template`), які враховують особливості парсингу XML/JSON-тегів кожної архітектури.
3. **Асинхронний делегований інференс для великих моделей:**
   - Модель `qwen3.5:27b` не повинна використовуватися в інтерактивному циклі. Її доцільно запускати у фоновому режимі (System 3) для періодичної нічної рефлексії (`src/b12/reflection.py`) та глибокого аналізу великих масивів документів, де затримка у 2–3 хвилини є допустимою.
4. **Контроль довжини реплік через параметри генерації:**
   - Для великих моделей обов'язково прописувати параметр `num_predict: 250` у запиті до Ollama API, щоб апаратно запобігати багатослівним есеям та зберігати стиль компаньйона.
