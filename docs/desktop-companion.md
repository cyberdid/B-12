# Desktop-компаньйон Capri

## Встановлення і запуск

Qt desktop-клієнт постачається як optional extra. У теці репозиторію встанови залежності:

```bash
uv sync --extra desktop
```

Потрібна ініціалізація власника (`b12 init`) і запущений локальний API (`b12` — внутрішній runtime namespace). Сервер запускається окремою командою:

```bash
b12 serve --port 8712
```

В іншому терміналі:

```bash
b12 desktop --url http://127.0.0.1:8712
```

`--url` необов’язковий; значення за замовчуванням — `http://127.0.0.1:8712`. Змінна `B12_API_URL` також може задати адресу. Клієнт приймає лише loopback URL (`localhost`, `127.0.0.1` або loopback IPv6); віддалений API відхиляється. Для графічного клієнта достатньо extra `desktop`; TUI extras не потрібні. Якщо owner token відсутній, спершу виконай `b12 init`.

## Вигляд компаньйона

Якщо локальний Capri pack валідний і користувач раніше не зберіг вибір, desktop-вікно відкривається з Capri. У контекстному меню й tray є **ВИГЛЯД CAPRI**: там можна перемкнутися на вбудованого Кіберкота. Вибір зберігається у legacy `QSettings` namespace для сумісності. Якщо pack зникне або стане пошкодженим, застосунок повертається до Кіберкота.

Pack за замовчуванням лежить поза репозиторієм у `~/.local/share/b12/skins/capri`. Пошук можна перевизначити через `B12_CAPRI_DIR`; для сумісності з TUI також читається `B12_TUI_CAPRI_DIR`. Для локального перегляду з pinned image-only checkout:

```bash
uv run --extra desktop python scripts/import-capri-skin.py \
  --source /path/to/capricorn-linux-checkout
uv run --extra desktop b12 desktop
```

Імпортер приймає лише revision `7752959e7a708bac5b540d5380321c33694f6fb6`, копіює PNG кадри та provenance, не виконує upstream code і за замовчуванням відмовляється перезаписувати наявний pack. Для іншого каталогу передай `--dest`; навмисне оновлення наявного каталогу потребує `--replace`.

**Межа прав:** upstream LICENSE поширюється на код і прямо виключає Capri character/Cyberpunk IP. Тому цей pack є приватним локальним preview за дорученням власника B-12; права на повторне поширення не встановлені. Не коміть pack, не додавай його до wheel або release. Відкрите питання про подальше розповсюдження лишається у [Q20](../wiki/project/open-questions.md).

## Що вміє клієнт

- Capri має цілісне перше-особове самосприйняття й власний cyberpunk-характер: спостережлива, дотепна, пустотлива, самостійна та уважна. Вона не додає шаблонних AI-дисклеймерів у звичайну розмову; про реальні можливості, пам’ять і технічну природу відповідає прямо. Деталі й межі — у [персоні та її джерелах](../wiki/sources/capri-personality-review-2026-11-08.md).
- Плаваючий прозорий Capri або Кіберкіт: pointer gaze, drag, клік, sleep/wake, сон після 10 хвилин без взаємодії з companion, reduced motion, локальний системний beep за бажанням, wander, peek, demo й ручне перенесення на дисплей під курсором. Необов’язкове слідування за курсором між дисплеями вимкнене за замовчуванням і вимикається з reduced motion.
- Capri має анімації, незалежні від моделі: реакції на натискання/перетягування й стани чату; появу, цікавість, розмову, відпочинок, peek, стрибок/падіння/кидок/перекид/KO, teleport, супутник/промінь, lightning, shards, shockwave, speed, святкування, glitch, cut-in і сон. Їх можна запускати з меню `АНІМАЦІЇ CAPRI`; рух і неонові ефекти процедурно малюються в Qt поверх наявного локального sprite pack.
- Tray/menu, якщо системне середовище надає tray. За наявності tray персонажа можна сховати й відкрити знову через меню.
- Компактна frameless-розмова, закріплена під/біля Capri: сесія, історія, streaming-відповіді, зупинка ходу, approval cards та кнопка розгорнути повний чат. Положення підлаштовується до меж екрана й переміщується разом із персонажем. Enter надсилає prompt, Escape ховає bubble.
- Локальні нагадування з ручним date/time та детермінованим розбором явних українських/англійських фраз. Перед збереженням показується точний текст і час; нечіткий або відсутній час відкриває форму уточнення. Є сповіщення, відкладання на 10 хвилин і закриття.
- Профіль Capri: ім’я користувача, власна нотатка стилю та фрази автоматично додаються як обмежений стильовий контекст до кожного desktop-запиту. Профіль зберігається локально; із хмарною моделлю ці поля надсилаються обраному провайдеру. Вони не змінюють інструменти, дозволи чи пам’ять. Історію взаємодії можна явно ввімкнути; вона зберігає тільки тип/час події, не текст чату.
- Інтеграції Claude Code, Codex та Antigravity встановлюються в їхні локальні JSON-конфіги лише після підтвердження. Hooks зберігають тільки тип події, час, HMAC-псевдонім сесії й лічильник; Antigravity отримує лише protocol-required pass-through для `PreToolUse`/`Stop`, без зміни B-12 grants. Є фільтр агента, activity ticker, локальний денний звіт і копіювання звіту як зображення в clipboard без запису на диск. Підтвердження зовнішнього агента треба натискати в його власному вікні.
- Власні швидкі фрази, owner-managed app launchers з абсолютним шляхом та argv; ярлики HTTP(S)-сайтів, що відкриваються тільки після кліку.
- Поле системної команди підставляє command/cwd у звичайну розмову Capri; виконання проходить через наявний `b12` runtime tool/grant/approval policy.
- Локальна панель шукає назви у вибраній теці (до 5 000 елементів); за окремою галочкою шукає у UTF-8 вмісті до 400 файлів (256 KiB на файл, 16 MiB загалом). Hidden entries та symlink traversal пропускаються, файли не зберігаються й не надсилаються. Панель показує системний зріз CPU/RAM/disk/battery/network та відкриває/показує шлях лише після підтвердження.
- Linux/X11 панель надає доступні `playerctl`, `wpctl`/`pactl`, lock/suspend/reboot/poweroff/cancel, GNOME color-scheme і XRandR display mode. Точний target видно до кліку; sleep/reboot/poweroff вимагають введення точної назви дії. Відсутній системний інструмент позначається як недоступний.
- Вбудована коротка інструкція та user-level XDG autostart manager з preview. Autostart вимкнений за замовчуванням і не перезаписує чужий чи вручну змінений файл.
- Черга точних owner approval/deny, пошук/додавання/видалення пам’яті, контроль згоди та панель стану.
- Перегляд стану голосового сервісу та перемикання його mute-прапорця через API.

Усі API-виклики виконуються поза Qt GUI thread. Owner token читається з наявного `$B12_STATE_DIR/api/owner.token` і надсилається лише у `Authorization: Bearer`; клієнт не копіює його, не пише у налаштування та не виводить у логи. Сесії, інструменти, grants, approvals, згода, пам’ять і модель залишаються під контролем B-12 API.

Desktop успадковує можливості автентифікованого owner API й поточну конфігурацію B-12. Він не створює нових grants. Shell-команди лишаються під control/grant/approval правилами runtime. Додатково за [ADR-011](../wiki/project/decisions.md#adr-011--desktop-launchers--system-commands) власник може створити локальний launcher: він запускається тільки після кліку й підтвердження, через absolute executable path і argv без shell parsing.

Після обриву стріму клієнт не приймає підтвердження запиту на зупинку за доказ завершення: лише після успішного cancel acknowledgement він перевіряє точний стан ходу через owner-authenticated API та оновлює історію після завершення. Поки свіжа історія не завантажилась, composer залишається заблокованим.

Якщо API тимчасово зникає під час очікування підтвердження дії, кіт зберігає approval-позу; після reconnect клієнт звіряє актуальну чергу й прибирає її, коли рішення більше не очікується.

Панель підтверджень завжди показує назву дії та короткий ідентифікатор. API черги навмисно не повертає аргументи очікуючої операції. Якщо аргументи надійшли у live-потоці, картка спрямовує до них у transcript; для старої/відновленої черги UI прямо попереджає, що параметри недоступні.

## Межі запуску й непокриті функції upstream

Кодова сумісність **ще не означає повного порту чи host acceptance**. Desktop не запускає B-12 server, Ollama/model або запис/відтворення голосу. Модель, grants, consent, пам’ять та approvals лишаються у B-12 runtime. Shell-команда надсилається у звичайний B-12 chat і підпадає під runtime permissions; локальні фіксовані дії мають окреме підтвердження. Зовнішні hooks — пасивні та opt-in; вони не підтверджують дії Claude/Codex/Antigravity і не створюють дозволів у B-12.

Screenshot/vision і періодичний screen watching недоступні: desktop chat API приймає лише текст. Не реалізовані active-window/USB/game sensing, auto-close/керування чужими вікнами, window possession, upstream art/sounds/cut-ins, screen recording, синтезовані/custom sounds і повний перемикач UI languages. У персонажа є незалежні Qt-аналогії fall/tumble, satellite/beam та screen-space FX, без upstream коду чи арту. Linux/X11 window-management еквіваленти, крім наявних XRandR display modes, позначаються як недоступні; Wayland host acceptance не виконаний. Знімок екрана не підмінюється удаваним текстовим аналізом.

Launcher дозволено за [ADR-011](../wiki/project/decisions.md#adr-011--desktop-launchers--system-commands): це явно додана власником пара executable+argv, ручний клік і окреме підтвердження перед запуском. Desktop не створює model-callable host tools або глобальних клавіатурних hooks. Голосові кнопки змінюють лише mute/status через API.

Перший deployment target — Linux/X11 із compositor. Прозорість top-level Qt widget у X11 вимагає ARGB visual і compositing window manager; `WindowStaysOnTopHint` є запитом до window manager. Tray залежить від StatusNotifierItem або XEmbed і має fallback, якщо недоступний. [Офіційні пояснення Qt QWidget](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QWidget.html), [window flags](https://doc.qt.io/qtforpython-6/PySide6/QtCore/Qt.html) та [QSystemTrayIcon](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QSystemTrayIcon.html). Wayland, інші дистрибутиви та фактична візуальна поведінка на різних window managers ще потребують перевірки.
